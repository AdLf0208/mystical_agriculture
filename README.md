# Mystical Agriculture for Horizon — slice 1

A clean-room Rust port of **Mystical Agriculture 1.21.1-8.0.29**
(`BlakeBr0/MysticalAgriculture`, MIT) for Horizon 26.3 on the SDK nightly
`0a875da91dbb0fdcb7ba8c42c11341aa229af51a` with horizon-mixins `e59da909…`.

This first slice is the **inferium crop/essence loop**: inferium seeds plant
`mysticalagriculture:inferium_crop` on farmland, it grows through the wheat
template's ages 0..7 on random ticks, a harvest drops the jar's essence and
seeds (farmland dependent), and 8 essence + a wheat seed craft seeds while a
prosperity ingot + 2 essence craft an inferium ingot. Bone meal is refused, as
upstream. The rest of the mod is a planned gap list (`notes.md`).

Slice 2 (0.2.1) put the carried crop loot table in 26.3's own dialect and ran the
package in game at the campaign pin; `notes.md` §Slice 2 records it.

## One package (the SDK format)

```text
mysticalagriculture.hmod        # the deliverable, built by `cargo horizon-mod build`
  horizon-mod.toml              # the only manifest: id/version/api/side + [native] pins
  Cargo.toml                    # one crate; depends on horizon-mod-api from .horizon/sdk/
  src/lib.rs                    # the one impl Hooks: register + loot_drops
  src/support.rs                # the crop's BlockPart (bone meal) and the loot hook's glue
  src/runtime.rs                # the pure rules (9 tests), byte-identical to the 0.1.0 file
  assets/mysticalagriculture/   # models, textures, blockstate, item definitions, lang
  data/mysticalagriculture/     # block/item declarations, recipes, the fallback loot table
  LICENSE, LICENSE-NOTICE.md, README.md
  uses.json                     # generated by the build: the API surface it uses
```

The carried files come from the exact ATM10 jar through
[`tools/carry_content.py`](tools/carry_content.py) (`--check` proves the tree still
matches); [`tools/data_shape.py`](tools/data_shape.py) checks the returned recipes
and loot tables against 26.3's dialect. Local-only until publishing is approved
(ARCHITECTURE.md §8).

## Run it

```sh
# the pure runtime, the lints and the package
CARGO_INCREMENTAL=0 cargo test
CARGO_INCREMENTAL=0 cargo clippy --all-targets -- -D warnings && cargo fmt --check
rm -f Cargo.lock && CARGO_INCREMENTAL=0 cargo horizon-mod build
cargo horizon-mod check target/horizon-mod/mysticalagriculture.hmod
cargo horizon-mod fits target/horizon-mod/mysticalagriculture.hmod --build 0a875da

# the carried content still matches the jar, and it is 26.3-spelled
python3 tools/carry_content.py --check
python3 tools/data_shape.py --data data

# the in-game legs: build the game once, then the native leg and the table leg
ports/tools/launcher-game.sh build mysticalagriculture
eval "$(ports/tools/launcher-game.sh env mysticalagriculture)"
tools/e2e.sh                  # native: SELFTEST=1 must exit 1
TABLE=1 tools/e2e.sh          # the carried table rolled without the code
TABLE=1 SELFTEST=1 tools/e2e.sh   # must exit 1
```

`build-slot.sh` and `tools/horizon.py` belonged to the retired `.hnmod` ladder;
this layout runs the new tool directly (see `AGENTS.md`). See `notes.md` for the
approach, the migration recipe, deviations, gaps and the verification table, and
`FINDINGS.md` for the upstream behaviour read.
